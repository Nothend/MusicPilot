# 推荐联动（ListenBrainz）详解

把 **ListenBrainz 的个性化推荐**（Daily Jams / Weekly Exploration / Weekly Jams）变成你 Navidrome 里能直接试听的歌单，闭环如下：

```
ListenBrainz 推荐 → 本地已有就直接复用 → 没有的从音乐平台下载【无损】到「试听库」
   → Navidrome 里试听 → 点红心 → 自动移入主库（转正）→ 红心还会同步回 ListenBrainz
   → 没点红心的，试听满 7 天自动清理（先进回收站）
```

**没有总开关，但危险的事都要你明确打开**：选了推荐来源，就会按各推荐列表的「启用」和定时时间自动获取并下载；「与 Navidrome 联动」（转正、过期清理）和「红心同步」默认关闭，需要你在页面里明确打开（打开联动前会弹出确认）。主库只会被**新增文件**（转正），绝不覆盖、绝不删除。

### 前置条件

1. **音乐平台 VIP**：推荐联动只下载无损。登录账号本身是 VIP 即可；否则在「设置 → 下载账号」添加并选用一个 VIP 借用账号。借用账号失效/不是 VIP 时任务会**直接失败并说明原因**，不会悄悄退回 MP3。
2. **Navidrome**（需支持多音乐库，实测 0.64.2），并在 Navidrome 里为你的账号填好 ListenBrainz Token、开启 Scrobble——否则 ListenBrainz 收不到你的听歌记录，也就生成不了推荐。
3. **目录映射**（本容器容器内只用这两个路径，页面里也只填容器路径）：
   ```yaml
   volumes:
     - /你的/音乐/主库目录:/music/songs          # 转正时往里新增文件；不用自动转正可加 :ro
     - /你的/音乐/试听库目录:/music/discovery    # 推荐歌曲先下载到这里
   ```
4. **Navidrome 侧**：给 Navidrome 容器**只读**挂载同一个试听库目录（如 `/discovery`），在 Navidrome 管理界面「音乐库」里把它添加为**第二个音乐库**，并授权给你用的账号。主库保持原样。

### 推荐为主、下载为辅：先获取，再按需下载

- **「立即获取推荐」只获取并显示推荐歌单**，同时与本地（下载目录 / 主库 / 试听库）比对：已有的标「已有」，本地没有的标「**待下载**」。它不下载任何东西。
- **旁边的「下载」按钮**才去下载，按「设置」里的方式走：**未联动 Navidrome** → 只下载到下载目录；**已联动** → 下载到试听库、生成 Navidrome 歌单，后续点红心转正。每首右侧还有单首「下载」；概览页也有同样的两个按钮。
- **「设置 → 下载渠道 → 自动下载推荐的歌」**（默认关闭）只管**定时同步**：打开后，定时获取到推荐就自动下载；关闭时定时同步也只获取。升级前已保存过设置的安装保持原来的「获取即下载」。

### 推荐来源（可选其一）

> **默认值**：全新安装默认「音乐平台每日推荐 + 仅下载到目录」（联动与红心同步默认关闭）。**升级前已经保存过推荐设置的安装保持原样**（ListenBrainz + Navidrome 联动），不会被悄悄改掉。

「设置 → 推荐来源」里选一个来源，「推荐」页和定时同步就只用它（切换不会删除已有记录和文件，切回来可继续）：

- **ListenBrainz**：每日熟悉 / 每周熟悉 / 每周探新，需要 ListenBrainz 用户名和 Token。
- **音乐平台每日推荐**（**全新安装的默认**）：取登录账号的「每日推荐」（约 30 首，平台每天 6 点刷新）。**不需要 ListenBrainz**；歌曲自带平台编号，按编号直接下载，不搜索匹配。同样走本地去重 → 试听库 → Navidrome 歌单 → 点红心转正 → 过期清理这条流程。在「推荐策略」里勾选「每天自动获取推荐」，并在「定时」里设同步时间（默认 07:30），每天自动获取当天推荐；也可随时点「立即获取推荐」。

### 与 Navidrome 联动：开关，默认关闭

「设置 → 音乐库与整理」顶部的**联动开关**（切换即保存；打开前会确认）决定怎么处理推荐的歌：

- 开关关（默认）= 下面的「仅下载到指定目录」；开关开 = 「与 Navidrome 联动」。联动开着时，手动下载的「音乐库去重」也直接用联动里填的那份 Navidrome 连接，不用填两遍。


- **与 Navidrome 联动**：就是上面描述的全套流程（试听库、歌单、点红心转正、过期清理、红心同步）。
- **仅下载到指定目录**（**全新安装的默认**）：**完全不连接 Navidrome**。推荐的歌下载到你填的「下载目录」就结束，没有试听库 / 歌单 / 转正 / 过期清理 / 红心同步，页面上这些入口也都会隐藏。
  - **绝不删除或改动**目录里已有的任何文件；下载先写进目录下的 `.staging`，完成后才移入。
  - 去重：读取下载目录（含子目录）里音频文件的标签，用与联动模式相同的规则判断「已有」（繁简、版本词、括号等）；还会参考「设置 → 下载渠道」里的「音乐库去重」（Navidrome / music-tag-web，只读查询；选「不使用」则只看目录）。
  - 结果状态：新下载的是「已下载」，目录或音乐库里已有的是「已有（跳过）」；下载失败 / 未找到 / 限流暂停的规则与联动模式一致。
  - 定时同步照常；转正、清理、红心同步的定时任务在这个模式下不触发。
  - 切回联动模式不会影响已下载的歌（「已下载」是终态，清理和转正都不会碰它）。

### 下载渠道

「设置 → 下载渠道」选择用什么把推荐的歌变成文件，目前只有「音乐平台」。渠道是可扩展的：新渠道只要遵守 `src/download_channels.py` 开头写明的约定（接收艺人+歌名、把合格的音频文件原子地放进指定目录、失败时返回分类好的错误），在 `lb_settings.CHANNELS` 与 `download_channels.FACTORIES` 里登记即可，流水线和页面不用改。

### 配置（「设置」页 → 推荐来源 / 音乐库与整理）

按顺序：ListenBrainz 用户名与 Token（测试连接）→ Navidrome 地址/账号（测试连接，然后在下拉里选「主库」「试听库」）→ 目录（填上面两个容器路径，点「检查目录」）→ 推荐策略、试听库策略、定时。以上是「与 Navidrome 联动」模式的配置顺序；打开联动开关之前，Navidrome 相关的项都不会显示。到「概览」点「立即同步推荐」即可开始。

| 设置 | 默认 | 说明 |
|---|---|---|
| 每种推荐的「最大新下载数」 | Daily 不限；Weekly 各 30 | 只统计成功下载的；本地已有的不占名额；0 = 不限 |
| 试听保留天数 | 7 | 从**首次进入试听库**起算；已红心 / 已转正 / 被「保留」的永不清理 |
| 回收站保留天数 | 7 | 清理先移入 `试听库/.trash`，到期才真正删除；0 = 不留回收站直接删 |
| 歌单保留天数 | 30 | 过期的推荐歌单（如 `LB Weekly Jams 2026-11-20`）会从 Navidrome 删除，只删我们自己建的 |
| 未找到冷却 / 下载重试 | 7 天 / 3 次 | 冷却期内同一首不重复搜索；下载失败按 30×n 分钟重试 |
| 多歌手连接符 | `, ` | 转正进主库时目录/文件名里多歌手的写法（如 `P!nk, Nate Ruess`）；填 ` / ` 会得到 MoviePilot 的全角斜杠写法 |
| 定时（容器 `TZ`） | 每日 08:30、每周一 10:00、转正每 30 分钟、清理 04:00 | 错过的时间点（如容器没开）不补跑；触发时已有任务在运行则稍后自动再试（时间点任务最多等 10 分钟，转正/红心同步一直等到能跑）。每日/每周同步遇到网络类失败（如 ListenBrainz 连接抖动）会每隔 10 分钟自动重试，最多 3 次，仍失败才发通知 |

### 它是怎么判断和处理的

- **只处理每种推荐最新的一份歌单**，同一份只处理一次；ListenBrainz 目前没有新歌单（它的生成取决于你近期的听歌活跃度）时，同步会正常结束，不是错误。
- **繁简体**：ListenBrainz 的歌手/歌名常是繁体（MusicBrainz 收录的写法），而你的库和音乐平台多是简体。程序**不做"先翻译再查"**，而是分三处各自处理：① 与本地库（Navidrome）比对时，把整个索引拉到本地，**双方都归一化成简体**（再忽略大小写、标点、拉丁重音）后比较，原文原样保留；② 向音乐平台搜索时直接用 ListenBrainz 的**原文**（音乐平台服务端繁简都认，实测同一首歌用繁体或简体搜，结果完全一致）；③ 搜到的候选同样归一化后再和推荐比对。写进文件标签、文件名、目录、歌单的名字一律来自音乐平台返回的名字，**不会把 ListenBrainz 的繁体写进你的库**。
- **本地查重**：按「歌手 + 歌名」匹配，自动处理繁简体、异体字、大小写、标点、拉丁重音（`Grégoire`=`Gregoire`）、多歌手写法，以及「拉丁名 + 中文名」的歌手别名（`F.I.R 飞儿乐团` = `F.I.R`）；**Live / Remix / Acoustic / Instrumental / Remastered 等版本不同不算同一首**，时长差超过 20 秒也视为不同录音（原版优先：库里只有 Live 时，原版照常下载）。
  **Radio Edit / 单曲版 / Explicit / Deluxe 等剪辑发行版**按「已有」处理、不再重复下载，时长容差放宽到 45 秒；若库里只有剪辑版而推荐的是原版，歌单里会提示「库里是『…』，建议尽快替换为原版」（程序不会覆盖主库文件，请手动替换）。主库优先于试听库。同一首歌本地有多个无法区分的候选时，记为「待选择」，在「推荐歌单」里手动选。
- **下载**：只要无损。音乐平台搜不到 / 只有 MP3 / 无版权的记为「未找到」；搜索被音乐平台限流时整轮**暂停**（不会误记成未找到），下次接着来。已下载的歌会写好完整标签（歌词、封面等）。
- **歌单**：在 Navidrome 里按歌曲创建，名称带日期；已在本地的歌也会放进去。
- **红心转正**：Navidrome 里标了红心的试听库歌曲，按你库里现有的命名规则（`歌手/专辑 (年份)/NN - 歌手 - 歌名.flac`）移入主库；目标已存在则**跳过并记录**，不覆盖；红心保留。
- **清理前可预览**：「概览」里的「待清理」数字，点「立即清理过期文件」会先显示将清理几首、受保护几首（红心/保留/已转正）。
- **红心同步到 ListenBrainz**（可选，**会真实写入你的 ListenBrainz，影响推荐**）：只增不减；优先用推荐歌单自带的 MBID，其次 Navidrome 标签，最后按歌手+歌名向 ListenBrainz 查询并**核对**，查不准的跳过。名字查询较慢（几百首红心首次要十几分钟），每轮最多查 100 首新的，其余下一轮继续。跳过的歌会列在「推荐 → 未解析的红心」里，可以搜索 MusicBrainz 选定正确的录音、粘贴 MBID，或标记「忽略」（见下方常见问题）。**建议先点「预览要提交的红心」看清会提交哪些**，再在「设置 → 红心同步」里打开开关。
- **通知**：配置了 Bark 时，只在任务失败、暂停、或有实质变化（新下载 / 转正 / 过期清理 / 提交红心）时才推送，没变化的定时空跑不打扰。
- 推荐任务与「手动下载」页的手动/定时下载任务共用一把锁：同一时间只跑一个；推荐任务在跑时再点按钮会提示「已有任务在运行」。

### 数据、升级与回滚

- 所有凭证、设置、推荐记录、任务日志都在 `./data/database.sqlite`（权限 600，含登录 cookie）。**必须放在本机磁盘，不要放在 NFS/SMB 挂载上**（SQLite 的 WAL 模式不支持）。
- **首次升级会把旧的 `data/web_state.json` 自动导入数据库，并改名为 `web_state.json.bak`**。升级前请先备份整个 `data` 目录。
- 回滚到旧镜像：需要把 `web_state.json.bak` 改回 `web_state.json`；迁移之后在页面里做的改动不会带回旧版本。数据库版本比程序新（降级镜像）时程序会拒绝启动，以免破坏数据。

### 常见问题

- **推荐歌单一直没有 Daily Jams，或 Weekly 停在很旧的日期**：这是 **ListenBrainz 没给你生成**，不是程序没取到——同步日志里会写「ListenBrainz 暂无该类型歌单」或「最新一份已处理过」，此时同步会正常结束，等它生成了会自动接上（每周一 10:00 的定时同步，或手动点「立即同步推荐」）。可以这样自查：
  - 「设置 → ListenBrainz → 测试连接」会显示每一类**最近一份歌单的日期**；
  - 确认 Navidrome 里填了 ListenBrainz Token 并开启 Scrobble，且你**近期持续在 Navidrome 里听歌**（生成与近期听歌活跃度有关，具体规则以 ListenBrainz 为准）；
  - 确认在 ListenBrainz 网站上**关注了官方机器人 troi-bot**。
  程序只能读取 ListenBrainz 已经生成好的歌单，生成这一步在它的服务端，这边无法催促。
- **Navidrome 里看不到试听库的歌**：检查 Navidrome 是否把试听库目录添加为第二个音乐库并授权给了你的账号；点「概览 → 扫描并同步索引」。
- **红心同步提示「有 N 首解析不出可信的 MBID，已跳过」**：ListenBrainz 的红心必须对应 MusicBrainz 里的一条录音（MBID）。多见于华语歌——MusicBrainz 里没收录，或歌手/歌名写法与你的文件对不上（程序宁可跳过也不会点到别的录音上）。点「推荐 → 未解析的红心」：每首会写明原因，可 **搜索** MusicBrainz 并点「就是它」、直接**粘贴** MBID（也可粘贴 musicbrainz.org/recording/… 链接），或点**忽略**（MusicBrainz 里本来就没有的）。处理结果永久有效，下次红心同步生效，可随时撤销。也可以用 Picard 等工具给文件打上 MBID 标签，程序会直接采用。
- **红心点了没有转正**：红心必须点在**试听库**里的那首歌上；然后等转正检查（默认每 30 分钟）或点「一键转正红心曲目」。主库已有同名文件时会在「推荐歌单」里标出「主库已有同名文件，未转正」。
- **有几首歌显示「已跳过」**：这一类推荐已达「最大新下载数」（Weekly 默认 30），超出的会记为已跳过，**不会自动留到下一轮**（下一轮是新的歌单）。想要的话在「推荐歌单」里点那首歌的「重试」，下次同步会处理；或在设置里调大上限（0 = 不限）。
- **推荐页顶部提示「推荐还不能运行」**：说明还缺什么配置（例如 ListenBrainz 的用户名和 Token、Navidrome 信息或下载目录），补全后即可；点「去设置」直达。
- **点按钮提示「已有任务在运行」**：推荐任务和「手动下载」页的下载任务共用一把锁，同一时间只跑一个；等当前任务结束（「任务记录」里选「推荐联动」能看实时日志）再点即可。
